# Module integration and rollout status

This records the scope of the backup and UniFi integration changes. It is not a certification of an entire production deployment. Existing module-specific controllers, jobs and workflows remain available.

| Area | Implemented behavior | Remaining work or deployment requirement |
| --- | --- | --- |
| Generic backup plans | Encrypted database persistence, versioned JSON import/list/delete commands, a local-archive restore command with validation by default and explicit `--apply`, expiring idempotency records and shared worker leases | Apply `Version20261117200000` and `Version20261117210000`; configure the existing schedule dispatcher and Messenger worker. This is separate from the module-specific `BackupDefinition` UI. |
| Backup archive pipeline | Private temporary workspaces, streaming gzip and AES-CBC processing, corresponding restore preparation and cleanup | Retain archive keys. Legacy AES-CBC archives have no cryptographic authentication. Owned plan/target leases renew during HTTP transfers, streamed archive/checksum processing and uploads. New module bundles authenticate their payload checksum and resource binding; the legacy outer AES-CBC format remains compatible. |
| Web restore | Rejects archive traversal, links and special files, and existing symlinks in destination paths; dry-run performs validation without writes | Validate real target permissions and backup/restore using non-production data before rollout. Tests cover the reproduced symlink overwrite; they do not establish protection against an attacker concurrently replacing filesystem paths. |
| Musicbot generic adapter | Exports the existing configuration manifest and restores supported configuration sections transactionally, with customer/instance/checksum validation | Configuration recovery only: media, live runtime state, queue/history/logs and other unsupported sections are not restored. Existing encrypted connection secrets are preserved. Masked credentials for a new connection must be configured before restore. |
| Generic Mail, Voice, Game and Database adapters | Four registered providers resolve persisted resources and encrypted credentials; authenticated bundles drive completed Agent filesystem/SQL operations. Mail includes routing/DKIM files and control-plane metadata; TS3 includes external SQL and files, TS6 its embedded data. | Apply `Version20261118010000`; configure administrator Agent/path/service bindings and Agent root allowlists. Enable plan encryption to protect payload contents at rest. Deploy the matching Agent API before enabling plans. |
| Musicbot full recovery | Separate administrator module `musicbot_full`: encrypted authenticated metadata, credentials, complete queue/history/logs/roles/limits and real media; preflight and file/database rollback on failure | Configure instance service/root and preserve installation encryption keys. Same instance/customer/node/path binding is required. Transient processes, sockets and tokens are rebuilt; customer configuration imports remain separate. |
| UniFi automatic port synchronization | Doctrine registration, transactional durable outbox, post-commit scheduler/CLI processing, retries, instance deletion handling and isolation of instance-owned rules | Apply `Version20261117190000` and `Version20261117191000`; run the central scheduler or `app:unifi:drain-sync`. External API behavior must also be checked against the deployed controller and permissions. Disabled integrations retain pending requests. |
| Generic backup retention | Encrypted inventory; opt-in local/WebDAV/Nextcloud/S3/SFTP/SSH/SMB/NFS retention, preview/apply CLI and scheduler, content/account/reference/lease checks; HTTP conditional deletion or verified quarantine | Apply `Version20261117210000`. Off by default. Use dedicated backup accounts/directories and review each target before enabling. Validate a real NFS export on the deployment host. Untracked, altered, shared, historical unbound or retargeted archives are retained or blocked. |

See [generic-backup-plans.md](generic-backup-plans.md) for plan import, key handling, worker leases and scheduling details. Provider setup is in [module-backup-providers.md](module-backup-providers.md), remote storage in [remote-backup-retention.md](remote-backup-retention.md), and full Musicbot recovery in [musicbot-full-recovery.md](musicbot-full-recovery.md). Agent API/setup details are in [MODULE_BACKUPS.md](../../agent/MODULE_BACKUPS.md). UniFi operator instructions are in [the documentation](../../wiki/Dokumentation.md).

Before rollout, take a database backup, review and apply the new migrations listed above, retain stable encryption secrets on all nodes, and validate the enabled operations on representative non-production resources. The port-allocation migration changes only the instance-owned allocation foreign key to cascading deletion. No production migration or remote-controller change is executed by the integration tests.

Tests use the real application kernel and providers, SQLite databases and filesystem archives. PHP 8.4/8.5 also exchange signed snapshots/restores with the real Go HTTP handler. Isolated native MySQL/MariaDB clients verify SQL snapshots, unchanged dry-runs, full restores and rollback after a deliberately failed SQL import; verified MySQL TLS uses the actual PEM CA contract. OpenSSH/SFTP, Samba/SMB and HTTPS WebDAV/Nextcloud/S3 fixtures exercise real transfers, checksums and deletion preconditions. Services are controlled by test fixtures; deployed Postfix/Dovecot, game/voice services, NFS exports and UniFi appliances still require site-specific verification. No production service was modified.

Database verification on 2026-11-17 used isolated MySQL 8.4.13 and MariaDB 10.11.19 servers: all 52 migrations (568 SQL statements) applied without warnings, the ORM schema diffs were empty, and full mapping/schema validation passed. Re-running migrations with PHP 8.4 on the migrated databases preserved existing scheduler-history rows. A native legacy-plugin upgrade also retained the source rows and copied the catalog without duplicates on repeated execution. JSON defaults remained an object (`{}`) and an array (`[]`) on both engines.

Earlier backup verification used the real handler to create two encrypted gzip archives with persistent inventory and idempotency records. The actual CLI preview preserved both files; apply deleted only the older archive. PHP 8.4 restored the remaining archive created by PHP 8.5. All fixture databases and files are separate from production.

Migration compatibility corrections:

- `scheduled_task_runs` and `game_plugins` are created by their existing owning migrations, `Version20260506120000` and `Version20260531120000`. Their duplicate baseline definitions were removed. Fresh installs execute those migrations normally. Existing recorded versions keep their tables and data.
- The Musicbot defaults in `Version20260624000000` and `Version20260624100000` use parenthesized SQL expressions, accepted by MySQL 8.4 and MariaDB. Migration identifiers remain unchanged; recorded versions do not replay.
- Oracle MySQL 8.4+ schema generation and introspection use DBAL's supported schema-manager factory and default-expression interfaces to represent empty JSON defaults consistently. MariaDB and SQLite keep their native schema managers; the database platform, query builders and query execution remain native. Different or absent defaults remain visible to schema comparison.

Agent creation, agent endpoint resolution, database-node inspection and mail DNS checks now have explicit service interfaces. Existing implementation methods and their behavior are retained; all 12 method bodies were compared before and after the contract refactor. Production consumers and test doubles use the interfaces, while direct implementation tests still exercise the real services.

Additional service and repository contracts preserve all 269 method bodies across 38 implementations. Their concrete classes are final; application dependencies and test doubles use explicit interfaces. Doctrine still receives the concrete repository classes, and inherited query builders, counts, lock arguments and ordered `findOneBy` calls remain available through the repository contracts. The complete Musicbot quota contract includes plugin, Discord, TS6, workflow, scheduler and usage operations.

Psalm's Doctrine integration records mapped-class discovery before class storage is cached and reconciles cached metadata before analysis workers start. CI uses a fresh analysis, and regression checks cover cold, parallel and cached scans, including grouped mapping attributes. Ordinary unused classes remain reported. The verified result is 305 remaining usage/structure findings; all 38 application-class finalization findings are resolved. No baseline or diagnostic suppression was added.

This contract refactor preserves existing runtime behavior rather than completing every legacy backend feature. In particular, `SinusbotInstanceRepository::countBotsUsedForInstance()` still returns a placeholder zero; a real usage provider remains necessary before that display can represent actual Sinusbot usage.

The TeamSpeak and Voice controllers/application services are consolidated under `Module/Voice`. Existing TS3/TS6 entities, routes, settings and native Agent execution remain authoritative. The generic Voice path now uses those actual jobs for actions and probes; customer bindings are checked before access. See [the module architecture and rollout notes](../architecture/voice-teamspeak-module.md) for the retained prepared abstractions and deployment limits.
